# Beyond the Harness: A Journey Towards Adaptive Engineering

## [核心摘要]

當前 AI 工程依賴「固定式 Harness」（如 Claude Code、Cursor、LangChain）——在工程開始前預先定義角色、工具與流程順序，類似工廠流水線，產出可靠且可審計。然而，隨模型能力呈指數增長且 AI 走向真實世界（多 Agent、多機構、觸及物理環境），固定 Harness 因抑制變異而變得脆弱且過時。Rajiv Chandegra 提出「**適應性工程**」：工程師僅設計約束條件（遊戲規則），讓 Harness 在工程過程中自我湧現、穩定、適應甚至消散，使 Harness 從「輸入」轉變為「輸出」。 

***

## [詳細重點整理]

### 1. 當前範式與未來挑戰 [00:00]

現有 AI 工程範式的核心是使用固定 Harness 來引導 Agent。典型工具包括 CLI 類（Claude Code、Codex、Pi）、IDE 類（Cursor）、多 Agent 編排框架（LangChain、Hermes、Klein、Goose）。所有角色、輸出格式、流程順序、記憶機制均在工程啟動前預先定義，可客製化但客製化發生在 runtime 之前而非 runtime 之中。

未來的兩大轉變：
- **模型能力指數增長**：今日精心建構的 Harness 可能在下個月因模型進步而顯得多餘
- **真實世界暴露**：AI 從螢幕背後走向多 Agent、多人類、跨機構、觸及物理世界，而真實世界是動態且混亂的

關鍵概念：**固定式 Harness（Fixed Harness）**

***

### 2. 固定式 Harness 的本質與優勢 [03:10]

Harness 的定義：模型是引擎，Harness 是圍繞引擎建造的一切，使其有用。固定 Harness 的三個核心優勢：
- **可靠性**：相同輸入產生相似輸出
- **可審計性**：可檢查具體變更的時間與內容
- **線性因果關係**：故障可追溯到源頭

類比為 **Taylorism for AI**——工廠流水線，每個站點預先工程化，每個 Agent 有固定位置、順序和交接。

關鍵概念：**Harness Engineering**

***

### 3. 固定式 Harness 的代價與侷限 [08:14]

可靠性並非免費——其代價是**抑制變異（variance）**，而變異正是新穎性（novelty）所需的。決定性（determinism）與湧現（emergence）朝相反方向拉扯。

真實世界中的固定 Harness 面臨「**脆弱性困境**」：每個未預期的情境都需要人類去修補 Harness，規則越加越多，最終 Harness 比實際要解決的問題還要複雜。

> 「工廠方法是固定問題的正確答案，卻是動態問題的錯誤答案。」

關鍵概念：**脆弱性困境（Brittleness Dilemma）**

***

### 4. 真實世界的本質：還原論 vs 關係論 [10:40]

兩種理解世界的範式：

- **還原論/分析範式**：世界由穩定的「事物」組成，變化只是偶爾發生在這些穩定事物上。關係是次要的。這是工廠與幾乎所有軟體的形而上學基礎。
- **系統/關係範式**：世界不由事物組成，而由**過程和關係**構成，關係優先於事物。所謂「穩定的事物」只是持續流動中的緩慢模式——如同火焰而非晶體：火焰看似物體，實則是由過程每時每刻維繫的模式。

Russell Ackoff 的觀點：管理者面對的不是整齊的分離問題，而是不斷變化、彼此碰撞的動態情境糾纏體——他稱之為 **mess**。Mess 不是分離部分的堆疊，而是運動中的關係系統，無法被分解為整齊的盒子逐一解決。

關鍵概念：**關係論範式（Relational Paradigm）**

***

### 5. 湧現：局部互動產生新秩序 [13:00]

當簡單的局部規則在粒子、人或生物之間運作時，互動會產生全新的秩序層級，無法從組成部分預測，也沒有任何部分事先設計。

兩個經典案例：
- **水的濕潤性**：氧和氫都不濕，但它們的結合湧現出濕潤這一新屬性
- **鳥群**：每隻鳥只遵循三條局部規則（與鄰居對齊、不碰撞、保持靠近），沒有一隻鳥醒來想組成鳥群，但鳥群湧現了。鳥群存在於關係中，而非部分中

工廠方法假設世界由部件組成；但非機器世界是模式與湧現的世界。

關鍵概念：**湧現（Emergence）**

***

### 6. 複雜問題 vs 繁複問題 [15:49]

兩種本質不同的問題類型：

- **繁複問題（Complicated）**：如建造巨無霸噴射機或時鐘。部件是被動的，專家可拆解、分析、規劃、預測。困難但可知，以可預測方式運作。
- **複雜問題（Complex）**：如鳥群、市場、人類組織。部件持續互動並互相適應，整體無法從分析部件推導。不能分析與規劃，只能**探測、感知、回應（probe, sense, respond）**。

現代設計與工程最昂貴的錯誤之一：將複雜問題當作繁複問題處理。失敗不是因為執行不力，而是因為問題空間分類失誤。

關鍵概念：**複雜 vs 繁複（Complex vs. Complicated）**

***

### 7. 複雜系統的核心要素 [17:24]

複雜系統的四個要素：
- **多樣性**：需要多樣化的 Agent，而非克隆體——多樣性是燃料
- **局部互動**：沒有任何 Agent 看到全局，各自只回應鄰近者
- **遞迴學習**：Agent 適應，然後適應自身適應的結果，不斷循環
- **湧現**：局部適應性循環互動中產生新穎的模式或組織

系統不會崩解為混沌，而是沉降入**吸引子（attractors）**——穩定狀態。局部層面持續變化，但整體系統層面呈現可辨識的穩定模式。關鍵是：沒有人掌舵，系統自我組織。

關鍵概念：**吸引子（Attractor）**

***

### 8. 適應性工程的定義與實踐 [20:53]

**適應性工程**的定義：

> 設計約束條件，使 Harness 自我湧現、穩定並按需適應不斷變化的環境，以你無法事先指定的方式。Harness 成為持續的**輸出**而非輸入。

具體實踐：給予 Agent 互動、學習、改變的能力後，組織從這些互動中湧現，以回應環境或目標，產生事先無法指定的全新秩序層級。Agent 創造 Harness，正如鳥與鳥之間的關係使鳥群得以湧現。

關鍵概念：**適應性工程（Adaptive Engineering）**

***

### 9. 湧現式 Harness 的模擬過程 [22:48]

模擬適應性 Harness 的湧現過程：

1. **初始狀態**：同構但未分化的 Agent 開始互動，起初只有零星交流
2. **耦合建立**：連接持續累積，直到平均每個 Agent 約有一條連接，系統整體開始湧現
3. **專業化湧現**：兩個 Agent 做相同事情時，環境壓力獎勵打破僵局的微小差異，差異被回饋放大直到兩者不再可互換——Agent 身份不是被賦予的，而是相對於其他 Agent 和環境所佔據的位置
4. **邊界湧現**：Agent 不再隨機連接，開始形成聚類，系統自行劃定邊界
5. **治理湧現**：規範與協議從局部協調中自發湧現，無需中央權威——「沒有統治者的治理」

關鍵概念：**湧現式專業化（Emergent Specialization）**

***

### 10. 工程師角色的重新定位 [26:27]

適應性工程不廢除工程師，而是**重新定位工程的重點**：

- **設計約束**：工程師設定遊戲規則，不決定應該發生什麼，而是給予 Agent 探索的空間
- **感知與回應**：一旦湧現式 Harness 開始成形，工程師感知並回應它，而非停止工程過程從頭開始

三個關鍵設計問題：
- **啟用 vs 約束**：給予 Agent 更多自由，還是更多護欄？
- **凝聚 vs 成本**：獎勵 Agent 朝目標凝聚，還是對偏離者施加成本？
- **速度調控**：耦合速率快或慢？

關鍵概念：**約束設計（Constraint Design）**

***

### 11. 固定式 vs 適應性：連續譜與案例 [27:20]

固定工程與適應性工程不是二元的「非此即彼」，而是一個**連續譜**：

- **Hermes AI**：自稱自改善的 AI Agent，從經驗中創造技能並學習——但這是**垂直智慧**（讓個別 Agent 更聰明）
- **Pi**：極簡但最大可擴展的 Harness，在設計階段高度可客製化——這是「設計階段的適應」，但不是 runtime 中的自我重組

適應性工程強調的是**水平智慧**（Agent 群體如何協調），論點為水平智慧是最具適應性、最敏捷且更高槓桿的方法。

關鍵概念：**水平智慧 vs 垂直智慧（Horizontal vs. Vertical Intelligence）**

***

### 12. 適應性工程的失敗模式 [33:19]

適應性工程的失敗模式：
- **吸引子陷阱**：系統趨向穩定結構，但穩定不等於最優——需要真實的選擇壓力，否則只是漂移
- **單一文化風險**：Agent 基於相同資料訓練，缺乏真正多樣性
- **可解讀性崩潰**：隨適應性增加，無法精確定位或解釋事物——這是複雜系統的固有特徵
- **預測性喪失**：runtime 前無法預測，因為一切持續運動

關鍵概念：**吸引子陷阱（Attractor Trap）**

***

### 13. 總結與展望 [35:08]

隨模型指數改善，AI 工程將進入真實世界場景——觸及物理空間、與多機構多 Agent 多人類持續接觸。設計工程學科將被迫圍繞**持續生產（continual production）**重新思考。

> 「限制因子不再是模型的強度，而是 Harness 的適應力。」

適應性意味著去中心化的多 Agent 協調，不是 runtime 前的適應，而是 runtime 中的適應——這才是真正的智慧。

關鍵概念：**持續生產（Continual Production）**

***

## [技術/數據對比]

### 固定式 Harness 工程 vs 適應性工程

| 維度 | 固定式 Harness 工程 | 適應性工程 |
|---|---|---|
| Harness 角色 | 輸入（預先定義） | 輸出（湧現產生） |
| 結構設計 | 工程師在 runtime 前施加 | Agent 在 runtime 中自我組織 |
| 控制方式 | 中心化、預先決定 | 去中心化、持續在現場調整 |
| 變異處理 | 抑制變異以換取可靠性 | 利用變異作為湧現燃料 |
| 適用問題 | 繁複（Complicated）、可預測 | 複雜（Complex）、動態 |
| 工程師角色 | 使用並微調 Harness | 設計約束、感知並回應 |
| 可預測性 | 高（線性因果） | 低（持續運動） |
| 可審計性 | 高 | 低（可解讀性崩潰） |

### 複雜問題 vs 繁複問題

| 維度 | 繁複問題（Complicated） | 複雜問題（Complex） |
|---|---|---|
| 部件關係 | 被動、穩定 | 持續互動、互相適應 |
| 解決方法 | 分析、規劃、預測 | 探測、感知、回應 |
| 整體與部分 | 整體可從部分推導 | 整體無法從部分推導 |
| 典型案例 | 巨無霸噴射機、時鐘 | 鳥群、市場、人類組織 |

### 水平智慧 vs 垂直智慧

| 維度 | 垂直智慧 | 水平智慧 |
|---|---|---|
| 核心焦點 | 個別 Agent 變更聰明 | Agent 群體如何協調 |
| 適應方向 | 單一 Agent 的能力提升 | 多 Agent 間的組織湧現 |
| 代表案例 | Hermes AI（自改善、技能學習） | 適應性工程（去中心化協調） |
| 槓桿效應 | 較低 | 較高 |

## [結論與行動建議]

### 啟發金句

> 「Harness 不再是你打造的輸入，而是你允許湧現的輸出。限制因子不是模型的強度，而是 Harness 的適應力。」

### 具體行動建議：C-S-R 法則

- **C — Constrain（約束）**：設計約束條件與遊戲規則，不預先決定結果
- **S — Sense（感知）**：觀察湧現式 Harness 的成形與變化
- **R — Respond（回應）**：在 runtime 中持續調整約束，而非停止重來

### 生活實踐建議

在團隊管理或產品開發中，當面對複雜且持續變動的問題時（如跨部門協作、新市場探索），不要試圖在事前定義所有人的角色與流程——設定清晰的目標邊界與互動規則，讓團隊結構在實作過程中自我湧現與專業化。若發現「規則比問題本身還複雜」，這就是固定式 Harness 已達侷限的訊號，應轉向探測-感知-回應的模式，讓組織成為關係的產物而非藍圖的執行。
