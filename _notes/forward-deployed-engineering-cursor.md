# Forward Deployed Engineering at Cursor — Pauline Brunet

## [核心摘要]

Cursor 的前瞻部署工程（Forward Deployed Engineering, FDE）是一個介於產品工程與客戶轉型之間的獨立職能，核心目標是與客戶共同設計、共同打造 AI 軟體工廠。FDE 解決的痛點是：企業導入 AI 工具時，缺乏能深入理解技術與業務、同時推動組織變革的橋接角色。Pauline Brunet 提出一套「客戶數位成熟度 × 產品可客製化程度」矩陣，明確界定 FDE 的適用場景與不適用場景，避免淪為傳統 SaaS 部署或人力外包，確保每個專案都能驅動可量化的 ROI。

***

## [詳細重點整理]

### 1. FDE 的定位與價值主張 [00:00]

Cursor 是 AI 編碼平台，產品線涵蓋從自主編碼、同步/非同步 Agent 到 AI 軟體工廠的完整路徑。Pauline Brunet 擁有 10 年企業級 AI 部署經驗，負責 Cursor 全球 FDE 團隊，她認為 2026 年將是 FDE 成為「最熱門職位」的關鍵年份。

**關鍵概念：前瞻部署工程（Forward Deployed Engineering）**

### 2. FDE 適用性矩陣 [01:49]

建構 FDE 團隊前，必須先評估兩個維度：

- **客戶數位成熟度**：客戶的技術能力與轉型進度
- **產品可客製化程度**：產品是開箱即用的 SaaS，還是高度可配置

由此劃分出四個象限：

| 客戶成熟度 | 產品客製化程度 | 建議策略 |
|---|---|---|
| 高 | 低 | 自助式提供，附良好文檔，FDE 介入價值低 |
| 低 | 低 | 傳統 SaaS 部署，瀑布式專案，非 FDE 適用 |
| 高 | 高 | FDE 擔任顧問角色，加速採用，推動極限用例 |
| 低 | 高 | FDE 進行嵌入式轉型，深度協作推動變革 |

FDE 的核心價值區域集中在「高成熟度 × 高客製化」與「低成熟度 × 高客製化」兩個象限。在低客製化場景中，FDE 不應淪為產品培訓或文檔更新工具。

**關鍵概念：FDE 適用性矩陣**

### 3. FDE 工程師的角色定義 [05:19]

FDE 是「技術極強且 EQ 極高」的獨角獸型人才，工作涵蓋：

- 跨層級溝通：從 CIO、CTO、COO 到開發者與工程經理
- 快速完成 Discovery：找出正確用例、理解現有流程
- 理解組織文化，推動變革管理
- 持續追蹤技術前沿，每週都有新發布
- 在產品工程團隊與客戶之間建立有效的回饋迴圈

Pauline 強調：「把最新最好的技術放進組織，卻不陪伴人員一起改變，沒有人會使用它。」

**關鍵概念：獨角獸型人才**

### 4. Cursor FDE 的實踐方法 [07:14]

Cursor 的客戶多為高度成熟的技術型組織，這決定了 FDE 的運作方式：

- **專案制、高影響力**：與經濟決策者或資深 Champion 合作，確保專案對齊公司戰略目標
- **共同開發**：在客戶的 codebase 上開發，部署 Cloud Agents、長時間運行 Agent、自動化流程，並基於 Cursor SDK 建構應用
- **推動邊界用例**：FDE 是「矛尖」，測試軟體開發生命週期之外的用例（HR、財務、供應鏈、電商、資產管理）
- **嚴防人力外包**：當客戶說「我們人手不足」時是紅旗信號，FDE 必須確保客戶投入資源共同建設

**關鍵概念：矛尖策略**

### 5. FDE Mission 與團隊結構 [10:37]

Cursor FDE 的使命宣言：

> 「我們與您的組織合作，共同設計與共同建造您的 AI 軟體工廠。我們轉變您在整個生命週期中設計、開發與維護軟體的方式。」

團隊結構特點：

- 初期招募「獨角獸」：5 年以上軟體工程師，具客戶面向經驗，不招應屆生
- 矩陣式組織，可快速調整
- 目前以地理區域劃分，未來將按產業垂直化（銀行需談支付系統、資產管理、風險）
- 按產品線設置 SME 專家（如長時間運行 Cloud Agent 專家、Cursor SDK 專家）
- 團隊成員來自 Spotify、Rippling、Palantir 等頂尖公司

**關鍵概念：矩陣式獨角獸團隊**

### 6. 最佳實踐 [13:19]

- **快速學習、快速調整**：不要等待完美計畫，直接與客戶嘗試專案，即使失敗也能學到更多
- **傾聽客戶**：Pauline 原本不打算提供的「組織變革諮詢」服務，因聽到 6-7 次相同需求而決定推出
- **與系統整合商合作**：SI 深入了解客戶、擁有關係，且能承擔變革管理等 FDE 不擅長的工作，擴大覆蓋範圍
- **勇於說不**：當 Cursor 不是正確工具時直接告知客戶，反而建立信任，帶來更多合適的用例
- **招募並留住對的人才**：A 級人才招募 A 級人才，B 級人才只會招募 C 級人才

**關鍵概念：信任式拒絕**

### 7. FDE 專案執行要訣 [16:07]

- **確認解決的是正確問題**：有時客戶描述的是症狀而非根因，要找到流程負責人深入訪談
- **從一開始定義成功標準**：「如果將流程從 3 小時縮短至 20 分鐘，對你來說算成功嗎？」
- **方向性 Scope 而非固定 Scope**：不要承諾「兩個 FDE 做六個月隨你安排」，而是定義問題、分階段交付、保持 pivot 彈性
- **客戶全程參與**：Scoping、建構、實施、Human-in-the-loop 驗證、基線對比、ROI 識別——客戶應主導，FDE 支撐
- **衡量成功與 ROI**：ROI 永遠是三件事——增加收入、降低成本、降低風險，至少達成一項
- **留下文檔與產物**：確保 FDE 離開後客戶能自主運營

**關鍵概念：方向性 Scope**

## [技術/數據對比]

| 維度 | 傳統 SaaS 部署 | 人力外包（Staff Aug） | FDE 模式 |
|---|---|---|---|
| 客戶參與度 | 低，交付即走 | 補人力缺口 | 深度共同開發 |
| 目標 | 產品上線 | 填補編碼產能 | 驅動戰略性 ROI |
| 客製化程度 | 低 | 依客戶需求 | 高，基於 SDK 建構 |
| 成功指標 | 部署完成 | 工時產出 | 可量化業務價值 |
| 離開後狀態 | 依賴持續支援 | 無持續價值 | 客戶自主運營 |

## [結論與行動建議]

### 啟發金句

> 「把最新最好的技術放進組織，卻不陪伴人員一起改變，沒有人會使用它。」

### 具體行動建議：M-R-I 法則

- **M（Matrix）**：用「客戶成熟度 × 產品客製化」矩陣判斷是否啟動 FDE
- **R（ROI）**：每個專案必須能回答——增加收入、降低成本、或降低風險，至少一項
- **I（Involve）**：客戶全程參與每一步，絕不孤軍奮戰

### 生活實踐建議

作為 AI 應用架構師，在推動企業 AI 導入時，可將 FDE 思維應用於內部專案：先評估目標團隊的數位成熟度，選擇高影響力、可量化的用例作為試點；採用方向性 Scope 保留調整彈性；確保業務負責人全程參與而非僅由技術團隊閉門造車；最後以「收入/成本/風險」三角框架衡量成效，留下完整文檔確保可持續運營。
