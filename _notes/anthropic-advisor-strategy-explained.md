## 核心摘要

本影片介紹了 Anthropic 推出的全新「顧問策略」（Advisor Strategy），這是一種將高效能的 Claude Opus 作為「導師」與成本較低的 Sonnet/Haiku 作為「執行者」配對的創新 API 應用模式。透過動態協作，不僅能提升任務處理的成功率，更能大幅降低 API 使用成本，為開發者提供了一個效能與經濟兼具的平衡點。

-----

## 詳細重點整理

### 1\. 顧問與執行者的協作模式 [[00:07](http://www.youtube.com/watch?v=hGYfsvlQ5Ok&t=7)]

  * **運作機制**：將最強大的 Opus 模型定位為「顧問」，負責制定計劃與解決疑難；將較便宜的 Sonnet 或 Haiku 定位為「執行者」，負責具體工作。
  * **動態回饋**：這並非單次指令，而是一個「持續互動」的過程。當執行者遇到無法解決的障礙時，會自動回頭諮詢擁有完整上下文的顧問模型。
  * **關鍵概念**：**動態協作流**（Dynamic Back-and-Forth），讓模型在遇到瓶頸時能及時修正，而非一路錯到底。

### 2\. 成本優化與工具調用限制 [[01:24](http://www.youtube.com/watch?v=hGYfsvlQ5Ok&t=84)]

  * **成本控制**：為了極大化降低費用，顧問模型（Opus）在過程中「不進行」任何實際的工具調用（Tool Calls），所有的實作動作皆由成本較低的小模型完成。
  * **數據表現**：影片指出在特定測試（如 Sweet Bench）中，這種混合模式比單獨使用 Sonnet 表現更佳，且每項任務成本從原本的費用大幅下降。
  * **關鍵概念**：**高低搭配（High-Low Pairing）**，用最昂貴的大腦做決策，用最實惠的勞力做操作。

### 3\. API 實作與應用場景 [[02:31](http://www.youtube.com/watch?v=hGYfsvlQ5Ok&t=151)]

  * **技術實現**：此功能主要針對 API 使用者。開發者只需在程式碼中調整 `type` 為 `advisor`，並設定 `max_uses`（諮詢顧問的次數上限）即可啟用。
  * **適用對象**：這對於開發網頁應用程式或自動化代理（Agents）的開發者來說是「無須思考」的必選方案，特別是當 Opus 太貴而 Sonnet 有時不夠聰明時。
  * **關鍵概念**：**找到效能中值**（Finding the Middle Ground），填補了原本在效能與成本之間的巨大鴻溝。

## 結論與行動建議

  * **啟發金句**：**「真正的效率不在於使用最強大的工具，而是在於如何聰明地將資源分配到正確的環節上。」**
  * **具體行動建議（3-10-5 法則）**：
    1.  **3 分計畫**：在啟動任何複雜任務前，先由「高階思維」定義出前三個核心步驟。
    2.  **10 分執行**：由「執行端」（或是你的大腦低耗能模式）進行 10 個具體動作的嘗試。
    3.  **5 分檢視**：一旦遇到無法決定的卡點，立即回頭對照最初的計畫，並進行最多 5 分鐘的修正與調整。
  * **生活實踐建議**：
      * **建立角色切換錨點**：在工作中練習「顧問模式」與「執行模式」切換。例如：早晨的前 15 分鐘扮演自己的「Opus 顧問」寫下今日計畫，其餘時間則全心投入「執行者」身分，減少猶豫時間。
      * **觀察紀錄**：記錄哪些任務最常讓你感到「卡住」，那些點就是你下次需要尋求外部建議或升級「顧問」支援的關鍵時刻。
