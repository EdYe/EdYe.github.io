## [核心摘要]

Anthropic 兩項大規模研究（23.5 萬人、40 萬次 Claude 工作階段 + 內部員工使用調查）揭示了頂尖 AI 使用者與一般人的六大差異：清楚溝通、善於回饋修正、讓產出易於審閱、把「一直沒做的工作」自動化、讓決策對 AI 可見、以及保持設定精簡。核心洞見是——**未來職場最重要的技能是「管理 AI」，如同管理一位能力強但只看得到你給的脈絡的員工**。

## [詳細重點整理]

1. 課題一：清楚溝通是最大分水嶺 

- 40 萬次 Claude Code 工作階段研究中，新手僅 15% 的時間獲得「經過驗證的成果」，專家則是兩倍以上。
- Anthropic 判定「專家」的標準不是職稱，而是：描述需求有多精確、要求 AI 檢查什麼、以及是你在糾正 AI 還是被 AI 糾正。甚至在寫程式任務上，主管得分高於工程師，因為主管習慣清楚說明「要完成什麼」。
- **關鍵概念：指令清晰度（Prompt Clarity）**——隨模型能端到端完成任務，「知道要什麼並講清楚」將成為跨職業的核心技能。

2. 四點交辦框架（主管心智模型）

每次交辦任務給 Claude，走過四個要素（建議用語音轉文字快速輸入）：

- **工作**：描述整個任務而非單一步驟。頂尖使用者做了約 70% 的計畫決策、卻只做 20% 的執行決策——你決定「做什麼」，留空間讓 AI 自己找「怎麼做」。
- **原因**：附上意圖。長任務中 AI 會遇到無數小決定，知道 why 才會用與你一致的方式判斷。
- **護欄**：花一分鐘設想哪裡可能出錯，寫成規則（例如：只使用 Fireflies 裡的通話）。語氣要放軟——Anthropic 指南建議避免「critical」「你必須」等字眼，新模型聽得太認真反而會做過頭。
- **完成樣貌**：新模型只在認為「完成」時停下來；不說明就只能用猜的。給檢查條件或範例（如：每個重點都要連到資料來源），並可要求「所有檢查通過前不要停」。Claude Code 創作者 Boris Cherny 認為，讓模型能驗證自己的工作是人們最常沒做好的事。
- 若講不清楚，通常是還不確定自己要什麼——可用「訪談我」技能讓 AI 反問，直到釐清後自動生成四點提示詞。
- **關鍵概念：交辦四要素**

3. 課題二：把糟糕輸出視為提示詞的回饋 

- 出錯時，新手 19% 的時間直接放棄，其他人僅 5–7%；專家讓 AI 產出理想結果的頻率是新手的四倍。
- 修正**最初的提示詞**勝過冗長反覆修改：在 Claude Code 用 `/rewind` 或按兩下 Esc 回到先前提示詞補上缺漏再重跑，避免把上下文塞滿錯誤輸出。
- 好回饋三件套：哪裡不對、為什麼不對、好的成果長什麼樣子。看不懂 AI 為何走偏就直接問它（Anthropic 的 Amanda Askell 的做法）。
- 加速技巧：要求一次給多個版本而非一個，更容易導向正確方向。還不夠就把 effort level 提高一級（如 Opus 中→高）再考慮換模型——且務必開新對話，中途換模型會失去快取、整段對話以全價重讀；改用「交接提示詞」（handoff prompt）貼到新對話。
- **關鍵概念：回饋式修正（Feedback Loop）**

4. 課題三：讓產出更容易審閱

- Anthropic 內部員工讓代理工作六倍於自己工時，但光是「閱讀」這些產出就花掉半個工作週；工作階段中約 80% 時間 Claude 只是閒置等人類回應。專家收到的回覆平均每則約 3,200 字，新手只有 600 字——越強，瓶頸越是你。
- 解法一：**輸出風格**。Claude Code 內建 `/output-style concise`；講者自訂風格讓每次回應依序以四件事開頭——(1) 需要我注意/提供意見的事項（人由上往下讀，預設放最後很沒效率）、(2) 到底有沒有達成目標、(3) 簡短摘要怎麼做到的、(4) 出錯的地方與原因——並保持簡短。
- 解法二：**視覺化輸出**。Andrej Karpathy：「視覺是大腦的高速公路。」任何要閱讀的東西輸出成單頁 HTML / 成品——研究與報告做成單頁設計或簡報、腦力激盪排白板、表格進試算表、分析建儀表板、需反覆修改的文案用 Claude Docs、複雜概念用 Motion 做解說影片。成品支援留言、手動修改與團隊協作，迭代更快。
- **關鍵概念：審閱吞吐量（Review Throughput）**

5. 課題四：自動化「一直沒做的工作」 

- Anthropic 內部研究中，員工估計 27% 用 Claude 完成的工作，沒有它根本不會被做；非技術員工在不到一年內，從每月 2 次寫程式工作階段增加到 90 次。
- 把問題從「我要怎麼做得更快」擴展成「有哪些事我從來沒做過，只因為覺得不值得花時間」（Alex Albert 稱為壓下「不值得」的第一反應）。實例：跟進 CRM 裡一年沒人理的潛在客戶、讓 AI 讀完所有客服通話產出客戶報告。
- 很多「大專案」現在不是了：講者拖著不做 Shorts，直到花 2 小時做一個把長影片腳本轉短影片的技能。
- 建議維護一份「**一直沒做清單**」，每週或每月跟 Claude 過一遍，問哪些能變成技能或排程任務。
- **關鍵概念：不可行工作解鎖（Unlocking the Undone）**

6. 課題五：把決策搬到 Claude 看得到的地方 

- 人做 70% 規劃決策、20% 執行決策，而決策大多發生在會議與聊天中；Anthropic 一般員工開會時間比一年前多 20%。Claude 只知道它讀得到的東西。
- 做法：讓 Claude 加入會議（目前僅限 Google Meet，或用 Fireflies 等轉錄工具），做筆記、記下每項決策；並在 CLAUDE.md 加一行「開始任何工作前，先閱讀今天所有通話的會議記錄」。
- 講者團隊的一場通話中，Claude 找出 62 項待辦事項、其中 48 項可直接執行。設一個排程任務：每小時檢查有無會議結束、把能做的待辦直接開始做、發送前拿草稿給人審核——會後 5–10 分鐘，你面對的是「審核佇列」而非待辦清單。回饋也會即時傳到團隊其他人的代理。
- **關鍵概念：決策可見性（Decision Visibility）**

7. 課題六：保持設定精簡 [16:37]

- 設定會隨使用不斷堆積：Anthropic 員工給 Claude 的常設指令一年內從幾百行長到 8,500 行；臃腫設定會載入每次對話，讓 Claude 更慢、更混亂、更貴。
- Boris Cherny 建議每 6 個月刪掉 CLAUDE.md、技能與 hooks，測試新模型裸奔能做到什麼。講者第一次整理時，Claude 找出 239 項過時、重複或從未使用的項目。
- 講者做了「排毒技能」，稽核五個部分：介面、技能、記憶與上下文檔案、連接器、排程任務，附建議處理方式，核准後清理。建議每兩週執行一次。
- **關鍵概念：設定排毒（Setup Detox）**

## [結論與行動建議]

**啟發金句**：最會用 AI 的人，就是最會管理的人——有了 AI，每個人都是主管，而 AI 只看得到你給它的脈絡。

**具體行動建議**：W-R-G-D 法則——每則提示詞依序涵蓋 **W**ork（要做什麼）、**R**eason（為什麼）、**G**uardrails（不可碰什麼）、**D**one（完成長什麼樣）。出錯時先 `/rewind` 修提示詞，再考慮提高 effort level。

**生活實踐建議**：

- 日常交辦任何 AI 任務前（如請 Claude 寫銷售摘要），先口述四要素，並要求 AI 在自檢通過前不要停。
- 立即在 Claude Code 執行 `/output-style concise`，並自訂「注意事項→達成與否→做法摘要→錯誤原因」的回應順序。
- 建立自己的「一直沒做清單」（例如：一直沒整理的舊影片素材、沒時間做的 Shorts），每月跟 Claude 過一遍，把可行項目做成技能或排程任務。
- 每兩週跑一次設定排毒，刪除過時規則、失效連接器與閒置技能。
