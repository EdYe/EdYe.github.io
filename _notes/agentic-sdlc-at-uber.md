## [核心摘要]

Uber 在 agentic AI 軟體工廠的實踐中，已讓超過 70% 的 PR 由本地或雲端代理程式生成，每位工程師的程式碼產出年增一倍。其核心貢獻在於建構六層基礎設施——模型閘道、MCP 閘道、代理化 DevPod、技能市集、情境圖譜與 Cortana 助理——系統性解決了代理程式在大型 monorepo 環境下的安全性、Token 消耗、上下文取得與工具編排等痛點，將原本分散於 20-30 套系統的工程知識收斂為統一、可歸因、可治理的代理程式執行平台。

## [詳細重點整理]

### 1. 效能數據：70% PR 來自代理程式 [00:00]

Uber 擁有數千名工程師，分布於 12 個全球技術據點。過去一年在 agentic AI 的投入帶來三項關鍵成果：超過 70% 的 PR 由本地或雲端代理程式提交、每位工程師的程式碼行數年增一倍、完成超過 250 項自動化遷移，涵蓋 900 萬行程式碼。六年前將程式碼庫遷移至 monorepo 並採用 Bazel 的基礎工程，為此加速奠定了根基。

**關鍵概念：Agentic SDLC（代理式軟體開發生命週期）**

### 2. 模型閘道與 100 毫秒護欄預算 [01:26]

所有模型呼叫（無論內部或外部）皆通過單一 OpenAI/Anthropic 相容端點，串接多層中介軟體：Spire 身份驗證、匿名化器（redacts 20+ 種 PII 類型）、五個專門安全模型組成的 AI Guard，全部在 100 毫秒內完成。系統每日承載超過 1 億次請求，涵蓋 800+ 專案，可歸因至個別呼叫者、使用者與團隊，並即時與資料湖中產生費用護欄。稽核日誌與 session traces 進一步回饋至基準測試與自我改善迴圈。

**關鍵概念：Guardrail Budget（護欄預算）**

### 3. MCP 閘道與 Token 稅削減 [03:51]

Uber 擁有數千個內部 API，但無一開箱即用於代理程式。MCP Gateway 以自動化爬蟲將內部 API 投射為 MCP servers，並以單一 config 變更完成；SaaS 工具（Google、Slack、Jira）亦統一由閘道代管 token exchange。Token 優化策略歷經三階段演進：直接 MCP → Omni MCP（單一 MCP 可發現並呼叫所有 MCP）→ CLI 模式投射（回應不佔用 context window）→ Code Mode Skill（自動生成 Python 腳本以超優化高 Token 消耗場景）。最終達成全艦隊 Token 使用量降低 40% 以上，支援超過 1,000 個 MCP 工具。

**關鍵概念：Token Tax Optimization（Token 稅優化）**

### 4. DevPod 代理化與預置 Balloon Pods [05:48]

既有 DevPod（雲端遠端開發環境）被重新設計為代理程式可用。核心需求為：長時間運行、快速啟動、隔離、可大量部署、跨全球據點可用。解決方案為預置 Kubernetes balloon pods——代理程式啟動時直接取用已預置的環境，倉庫已 snapshot 完成、搜尋索引已建立，數秒內即可開始工作。另推出 Mega DevPod，整合所有語言（Go、Java、Android）的所有倉庫於一處，供自主編碼代理程式跨倉庫工作；非工程師員工亦可在數秒內啟用任何代理程式工具。

**關鍵概念：Pre-provisioned Balloon Pods（預置氣球 Pod）**

### 5. 技能市集與品質治理 [07:18]

工程師在各倉庫中大量自建 skills，產生三個問題：重複建置、發現與設定困難、品質參差不齊。Uber 建立完整的 skill 生命週期管理：核心技能與領域技能進入統一市集，經 lint checks 與自動化審查確保基線品質，以單一指令完成發現與安裝，並依工程師角色自動安裝預設技能。目前市集有 2,500 個 skills，每日執行超過 20,000 次。最新投入為收集 traces、評論與持續評估，回饋給技能作者以持續改善。

**關鍵概念：Managed Skills Marketplace（託管技能市集）**

### 6. 情境圖譜與 4,000 萬條目 [08:39]

代理程式在大型 monorepo 中花費大量時間尋找基本上下文（服務位置、相依性、所有權、設計模式），散落於 20-30 套不同系統中，各自需要獨立 skill 與 MCP。Uber 將整個公司的運作知識整合為單一情境圖譜，包含 150 種節點與邊類型、4,000 萬條目，涵蓋行動 App、後端、資料湖、設計文件、Jira、事故與缺陷等。以「查詢印度現金支付行程數」為例，代理程式需理解概念、表結構與城市分類以生成 SQL——有無圖譜在 Token、對話輪次與延遲上均呈現顯著改善。

**關鍵概念：Context Graph（情境圖譜）**

### 7. Cortana：跨介面的 AI 助理 [10:19]

所有建構模組（skills、MCP、context graph）整合至 Cortana——Uber 的 AI 助理，覆蓋 Slack、CLI、Web 等所有介面。員工可提出問題，Cortana 查詢圖譜、呼叫技能、檢查任意程式碼庫並回應。近期開放個人化：員工可掛載自訂技能與 prompt 至團隊 Slack 頻道，使其如同團隊成員。過去一個月已建立 300+ 個角色，每日超過 20,000 個 session。

**關鍵概念：Ubiquitous AI Assistant（無所不在的 AI 助理）**

### 8. 端到端功能開發：從 Slack 起點到原型 [11:34]

以世足賽場館附近改良接送點為例，展示完整流程：在 Slack 討論想法 → 標記 Cortana → 以 context graph 評估商機 → 切換至 Web 介面進行商業研究（歷史大型場館活動、候選球場）→ 定義產品需求（北美限定）→ 以 Figma 製作 A/B 實驗 mock-up → Cortana 分析既有 App 與後端可複用資源。此流程原需數週對齊，現壓縮至極短時間內完成原型。

**關鍵概念：Compressed SDLC（壓縮式軟體開發生命週期）**

### 9. Minion 代理與刻意的 CI 停止點 [13:28]

從 Cortana 交接至 Minion（Uber 雲端編碼代理），以 DevPod 驅動完整建置環境，支援互動與自主模式，可跨前後端倉庫工作。關鍵設計決策：Minion 僅建立 draft PR，刻意不推送至 CI。原因在於驗證需前移至 inner loop——啟動模擬器、截圖並與 Figma 規格比對、於 staging 環境驗證前後端整合——避免大量未經驗證的 diff 湧入 CI 造成容量負荷。PR 附加表格記錄所有檢查步驟（含截圖），給人類審查者信心。

**關鍵概念：Validation Shifting（驗證前移）**

### 10. 維護即託管迴圈 [16:01]

功能上線後，可將服務註冊至維護技能。以 feature flag cleanup 為例：世足賽 A/B 實驗結束後，B 變體不再需要，系統在週日（CI 容量較充裕）排程自動清理，並控制週一 diff 數量避免工程師過載。技能執行產生的 diff 評論與落地結果成為 label data，回饋改善技能本身。每月從事故回顧中學習並轉化為新的維護技能，套用至所有服務。

**關鍵概念：Managed Maintenance Loop（託管維護迴圈）**

### 11. 瓶頸轉移至決策本身 [17:29]

基礎設施承載更多壓力後，新瓶頸浮現：CI 容量需預估與投資、可執行的實驗數量有限。最終，核心問題從「能否建置」轉為「是否應該建置」——決策本身成為新的約束。

**關鍵概念：Decision Bottleneck（決策瓶頸）**

## [結論與行動建議]

> **「能建不代表該建——當建置成本趨近於零，判斷力就是唯一稀缺的運算資源。」**

**具體行動法則：G-M-S-C-K 法則**

建立 agentic SDLC 時，依序檢視五層是否就位：
- **G**ateway（閘道）：統一入口、身份驗證、PII 護欄、可歸因
- **M**CP（工具編排）：消除 Token 稅，以 CLI 投射與 code mode 優化
- **S**kills（技能市集）：品質治理、自動安裝、持續評估回饋
- **C**ontext（情境圖譜）：收斂分散系統，降低 Token、延遲與不確定性
- **K**nowledge loop（知識迴圈）：維護技能 → 標籤資料 → 技能改善 → 新技能生成

**生活實踐建議**

在日常工作或內容創作流程中，可將 agentic SDLC 的思維應用於個人生產力系統：
- 建立「個人模型閘道」：所有 AI 工具呼叫集中於單一入口（如統一 prompt 模板與 API key 管理），記錄使用量與成本，避免散落各處無法歸因。
- 建立「個人情境圖譜」：將分散於 Notion、Google Drive、Slack 的專案脈絡整合至單一知識庫（如 Obsidian graph），讓 AI 助理能快速取得完整上下文而非逐處爬梳。
- 將重複性工作（如影片逐字稿整理、SEO 標籤生成、行程比價）抽象為可重用的「技能」，建立個人的技能市集並持續以執行結果回饋改善。
- 在內容創作流程中實踐「驗證前移」：在發布前於內迴圈完成多版本比對（A/B thumbnail、標題測試），模擬 Uber 的 Figma 比對邏輯，降低外迴圈（平台發布）的試錯成本。
