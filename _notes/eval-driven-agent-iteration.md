## [核心摘要]

Google YouTube 廣告團隊分享如何透過 **Evals（評估系統）** 與 Prompts 的迭代迴圈，打造可靠的生產級 AI Agent。核心痛點在於生成式 AI 輸出具非確定性，單靠 Prompt 無法穩定控制行為。團隊提出一套從「直覺式快速迭代」到「規模化評估」的漸進策略，涵蓋工具優化、獨立評論代理、Agent Trace 日誌分析、LLM-as-Judge 校準，以及上線回歸判定，形成完整的品質爬坡（Hill Climbing）迴圈。

***

## [詳細重點整理]

### 1. Agent 建置基礎與評估必要性 [00:00]

構建 Agent 困難且耗時，讓它在生產環境中可靠運行更難。生成式 AI 輸出非確定性高，同樣輸入可能一次成功、一次失敗，無法保證在真實場景中的行為表現，因此需要 Evals 作為規模化測量與品質管控的手段。

**關鍵概念：非確定性管控**

### 2. 工具優化與獨立評論代理 [01:19]

在進入大規模 Agent 評估前，應先建立扎實的基礎：
- 優化一組聚焦且 LLM 友善的工具集，確保工具本身效能最佳化
- 建立獨立評論代理（Critique Agent）搭配修復迴圈（Remediation Loop），作為自我修正機制，填補基礎工具的局限性
- 基礎結構定義完成後，再進入評估階段

**關鍵概念：獨立評論代理**

### 3. 可靠性方程式 [02:45]

Agent 可靠性是三個要素的函數：

\[ \text{可靠性} = f(\text{能力}, \text{護欄}, \text{評估}) \]

Evals 的作用是定義「什麼是好的輸出」，藉此讓 Agent 在真實世界中可被衡量。要讓 Evals 能規模化，必須嚴格且可量化。

**關鍵概念：可靠性三角**

### 4. 早期「直覺式」開發策略 [03:58]

專案初期不必急著建構完整的大型評估系統，反而建議採用 **Vibing**（直覺式方法）：
- 先觀察輸出，快速辨識問題所在
- 此階段 Prompt 微調可帶來大幅效能提升
- 允許架構層面的激進變更，不受制於僵化評估框架
- 深度理解失敗模式後，再進入目標導向的精準優化

若過早導入規模化評估系統，會因反覆校準評估標準而導致大幅震盪，反而拖慢迭代速度。

**關鍵概念：Vibing（直覺式開發）**

### 5. 小規模起步與負面測試 [06:03]

- 不需在第一天就建立龐大 Golden Set，從少數核心任務開始
- 逐步擴展至更細部的覆蓋
- 測試負面情境同樣重要：確認模型「沒有做壞事」與「做了正確的事」同等關鍵

**關鍵概念：負面測試**

### 6. 規模化評估者的最佳實踐 [07:10]

引入跨職能團隊與規模化評估者（Scale Raters）時的關鍵做法：
- 提供清晰的評分準則（Rubric）與具體範例，減少邊界案例的爭議
- 團隊內部需對「好案例」與「通過案例」達成高度共識
- 要求評估者提供**解釋**而非僅標記 Pass/Fail，才能定位 Agent 的具體弱點
- 多輸出場景（如同時評估準確性、品牌安全、預期一致性）需多維度評分，解釋能幫助拆解各維度表現

**關鍵概念：評分準則透明化**

### 7. LLM-as-Judge 校準方法 [09:42]

使用 LLM 作為自動評估者時：
- 建立取樣管線，監控人類專家與 LLM 評分的一致性/分歧率趨勢
- 確認一致性在合理範圍內
- 超越 Pass/Fail，結合 Agent Trace 進行抽樣推理檢查
- 維持高品質 Golden Set：覆蓋廣泛使用案例，且團隊內部人際一致性高

**關鍵概念：一致性監控管線**

### 8. Agent Trace 日誌揭示隱藏失敗 [11:02]

團隊在 Prompt 中明確告知 Agent「法律免責聲明不可移除」，但邊界案例中 Agent 仍會移除。單看 Pass/Fail 比率無法發現此問題，必須檢查 **Agent Trace（推理追蹤日誌）**：

> Trace 顯示 Agent 偵測到免責聲明存在，但隨後仍決定移除——這是推理邏輯與指令之間的衝突。

範例圖片為一則公共公園廣告，底部含「paid by the community of parks」免責聲明，Agent 在明確指令下仍將其移除。

**關鍵概念：Agent Trace 分析**

### 9. 泛化性與測試集管理 [12:27]

- Agent 的泛化能力受限於訓練資料集，需準備邊界案例測試集
- 沿用傳統 ML 概念：建立 Test/Validation Set
- 測試集應謹慎使用，並定期以生產資料刷新

**關鍵概念：測試集刷新策略**

### 10. 品質爬坡迭代迴圈 [13:01]

Hill Climbing 迴圈流程：
1. 執行人類評估
2. 達標則完成；未達標則進入迭代
3. 檢視 Eval Set，計算 Precision/Recall
4. 調整評分指南、模型或 Agent 工具
5. 同時迭代 Eval 與 Agent，形成雙向優化迴圈

良好的 Eval 定義完成後，此迴圈能有效驅動品質提升與消融實驗（Ablation）。

**關鍵概念：雙向迭代迴圈**

### 11. 上線就緒與回歸判定 [14:19]

- 辨識模型效能退化的位置與原因，區分「可接受取捨」與「關鍵失敗」
- **聚焦模式而非孤立案例**：不要因單一失敗案例就急改 Prompt，因系統具非確定性，應觀察整體模式中的失敗頻率
- Golden Set 需涵蓋多個能代表特定模式的範例
- 投資線上評估，確保資料符合真實世界分佈

**關鍵概念：模式優先原則**

### 12. 生產級 Eval 系統總結 [15:53]

一套好的 Eval 系統具備以下特徵：
- **代表性**：反映產品應擅長的領域，MVP 階段與生產上線階段的標準不同
- **持續演化**：線上評估、測試集以生產資料刷新、取樣管線持續運作
- **高品質 Golden Set**：隨使用案例演化而擴展
- **團隊培訓**：訓練評估者與跨職能團隊，建立統一評分標準
- **評估模板與準則**：附帶清晰範例，減少「不確定」標記
- **明確上線門檻**：定義 Precision/Recall 或其他指標作為 Gatekeeping 規則

**關鍵概念：演化式評估系統**

## [結論與行動建議]

> **「別讓單一失敗綁架你的 Prompt——要看模式，不是看個案。」**

**F-R-A-C 法則（評估驅動迭代）：**

- **F**oundation：先優化工具與基礎結構，再進入大規模評估
- **R**ubric：為所有評估者提供清晰準則與範例，要求附帶解釋
- **A**gent Trace：不只看 Pass/Fail，深入檢視推理日誌找出邏輯衝突
- **C**limb：建立 Eval 與 Agent 的雙向迭代迴圈，聚焦模式而非孤立案例

**生活實踐建議：**
在 AI 產品開發中，將「評估」視為與「開發」同等重要的第一公民。初期用直覺快速探索，但務必在進入規模化前建立可量化的 Golden Set 與上線門檻。每次 Prompt 或模型變更後，先跑 Golden Set 確認無回歸，再透過 Trace 分析定位新問題——這套迴圈能讓你在非確定性系統中穩定地爬升品質階梯。
