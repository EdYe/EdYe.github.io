# 【核心摘要】

Anthropic Claude 應用程式首席工程師 Felix Rieseberg 觀察到：頂尖 1% 的 AI 使用者與一般人的差異不在工具，而在「企圖心（Ambition）」。他將其拆解為三個可操作層次——**高度（Altitude）**：要求結果而非任務；**深度（Depth）**：讓 Agent 以頂尖專家的工具、目標與驗證方式工作；**廣度（Range）**：引入跨領域視角找出「未知的未知」。三者共同指向**自我效能（Self-efficacy）**：當模型能力每幾週躍進一次，你敢要求多少，決定你能獲得多少。

---

## 【詳細重點整理】

### 1. 開場：遲到學生的啟示

1939 年，學生 George Dantzig 遲到進統計課，把黑板上兩道題當作業抄下，隔天交卷——那其實是兩道**從未被解開的統計難題**，他解開了，只因為他不知道它們無解。Felix Rieseberg（Claude App、Claude Code 桌面版與 Cowork 的工程負責人）在 X 上發表的文章《How to Be More Ambitious: A Tutorial for Humans with Models》累積超過 450 萬次瀏覽，核心論點即為：頂級使用者的差別不是技術，而是不知道「不可能」。

- **關鍵概念：企圖心落差（Ambition Gap）**——「有些人已經在駕 AI 起飛，多數人還在拍打剛長出的翅膀」。

### 2. Felix Rieseberg 是誰

Anthropic 首席工程師，主導 Claude App、Cowork 與 Claude Code 桌面應用的工程團隊，等於親手打造了我們每天在用的 Agent 產品，其觀察來自一線工程視角。

### 3. 第一層次：高度（Altitude）

多數人給 Claude 的其實是「任務」，而任務只是你對如何達成目標的**最佳猜測**。高度的意思是：直接要求**成果（Outcome）**而非任務。

- 自問兩個問題：「我真正想讓接下來發生什麼？」、「目標背後的目標是什麼？」
- Felix 的實例：他原本逐一請 Claude 修復 App 當機問題，後來改為要求「讓這些 App 保持零當機」，結果產出他所謂的**持久工作流（Durable Workflow）**——一個能把人類移出迴圈的流程，不再需要一次次餵任務。
- 商務範例：簡報任務。多數人叫 Claude「填滿簡報模板」；但若真正的目標是「讓客戶被說服」，Claude 可能回傳可互動、可動畫的 HTML 投影片，甚至用可探索的 3D 場景取代平面場地圖。
- **限制**：高度適用於有明確可定義成果的目標（如零當機），目前對純創意工作效果較差——「去賺錢且別出錯」這種層級 2026 年的模型還做不到；但模型能力越強，可承接的抽象層級就越高。
- **關鍵概念：目標的目標（The Goal Beyond the Goal）**

### 4. be-ambitious 技能包 

講者將影片中所有資源、Prompt 與方法整理成免費指南與一支 `/be-ambitious` skill，可直接安裝給你的 Agent，讓它在執行任務時自動套用這三層企圖心原則。

### 5. 第二層次：深度（Depth）

深度 = 讓任務以**該領域頂尖專家的方式**完成，而非只「聽起來像專家」。Felix 警告：叫模型「像專業人士一樣」，它通常只會**換一套詞彙**，方法不變。三個技巧（以虛構公司 Acme 的客戶流失問題為例）：

1. **堅持使用頂尖專家的工具**：處理大規模客戶流失，專家會用資料科學工作流，不是聊天視窗裡的簡單表格。你不需要知道專家用什麼——模型自己知道，你要做的是在它伸手拿次級工具時推回去：「這真的是該領域最好的人會用的嗎？」
2. **設定聽起來不合理的高目標**：網站載入要從 10 秒降到 5 秒？直接要求 1 秒甚至 200 毫秒。模型說不可能時，告訴它「這非常可解，繼續做」。
3. **外部評審（Outside Judge）**：最重要的任務絕不讓模型自評。現今模型過於順從（Agreeable），幾個 Prompt 就能說服它自己是對的。作法是強制外部驗證——例如每次修改後自動跑速度測試工具；創意工作則派出**子代理（Sub-agent）擔任評審**，多項獨立測試證實能有效提升產出品質。

Felix 本人的一鍵深化 Prompt，讓 Claude 動工前先回答四個問題：

- 頂尖專業人士會做什麼「你沒被要求做」的事？
- 他們會從什麼**最原始的材料**開始？
- 他們會用哪些**方法與工具**？
- 除了你（Claude）之外，什麼能**證明結果是對的**？

然後讓 Claude 據此重寫你的 Prompt 再執行。

- **關鍵概念：外部評審原則（Outside Validation）**

### 6. 第三層次：廣度（Range）如果高度是一千英呎俯瞰、深度是把單一任務推到極限，廣度就是**橫向展開**——從其他領域的視角檢視你的工作。目的在找出**未知的未知（Unknown Unknowns）**：你根本不知道存在的選項。例如 Felix 直到看見同事用 Blender 渲染室內設計，才想到可以叫 Claude 為網站建 3D 環境。

兩個技巧：

1. **名詞換動詞**（出自《The Art of Innovation》）：QBR（季度業務回顧）的名詞是「PowerPoint 簡報」；動詞則是「讓忙碌的人在 30 分鐘內相信一個關於因果的故事，並在不確定中做出決策」。動詞一出口，目標與可用領域立刻清晰。
2. **組建團隊（Assemble the Crew）**：如同搶劫電影開場召集五人小隊，堅持讓 Claude 引入多重角色與觀點——分析師、業務經理、平面設計師，以及一個**紅隊（Red Team）**專門找漏洞、扮演魔鬼代言人。

實例：房仲賣房。名詞是「房產列表頁」；動詞是「讓一個家庭在看房前就能想像他們在這棟房子裡的生活」。轉成動詞後，Claude 可以化身室內設計師布置每個房間、3D 藝術家做走覽、在地人推薦附近餐廳——產出不再是通用頁面，而是針對該專案客製的成果。

注意：部署多個子代理消耗大量 Token，建議只用於最重要的工作。

- **關鍵概念：未知的未知（Unknown Unknowns）**

### 7. 底層理論：自我效能（Self-efficacy）

三層次背後的共同機制是心理學的**自我效能**——你相信自己能辦到的程度。35 年以上的目標設定研究支持三個駭客技巧：

- **相信它可能**：George Dantzig 解開兩道無解難題，因為他以為是作業。
- **看別人做到**：數十年無人能跑進 4 分鐘一英里，Roger Bannister 在 1950 年代突破後，幾天內就有人跟上。
- **允許自己失敗**：持續發布、每次改進，最終會成功。

在能力每幾週躍進一次的 AI 時代，自我效能是可以被放大的槓桿。

### 8. 企圖心仍需要「為什麼」

講者的反思：企圖心需要配速，更需要找到背後的 Why。否則只會越跑越快、越來越有野心，卻沒有明確理由。拿這些技巧提升對 AI Agent 的要求之餘，記得你為何而做，必要時允許自己暫停。

## 【技術/數據對比】


| 維度           | 一般使用者           | 頂尖 1% 使用者                     |
| ------------ | --------------- | ----------------------------- |
| 給 Claude 的指令 | 給任務（填滿簡報模板）     | 給成果（讓客戶被說服 → 互動式 HTML/3D 投影片） |
| 專業度          | 說「像專業人士」        | 堅持專家的工具、原始材料與外部驗證             |
| 目標設定         | 合理目標（5 秒載入）     | 不合理目標（200 毫秒），並要求持續推進         |
| 品質把關         | 讓模型自評           | 外部工具或子代理評審、紅隊攻擊               |
| 視角           | 自己單一視角          | 多角色子代理（分析師、設計師、紅隊）找未知的未知      |
| 問題表述         | 名詞（做一份簡報、一個列表頁） | 動詞（讓人相信故事、想像生活）               |

## 【結論與行動建議】

**啟發金句**：「你解不開的，往往不是你不會解，而是你不知道它其實有解。」

**具體行動建議 —— A-D-R 法則**：每次交付任務給 Claude 時依序檢查三件事——**A**ltitude（這是成果還是任務？）、**D**epth（頂尖專家會用什麼工具與驗證？）、**R**ange（有沒有第二個領域的視角可以進來？）。三者都過關再送出。

**生活實踐建議**：

- 把每週固定重複交付給 Claude 的一項工作（例如 YouTube 影片描述整理、程式碼修 Bug、Gitea Actions 的工作流維護）改寫成「成果導向」的持久工作流，例如「讓這條 pipeline 保持全綠」取代「修這次失敗的 job」。
- 在你的 MCP Agent 工作流中固定加入一個「紅隊」子代理與一個外部驗證工具（測試、速度測試、資料檢核），落實外部評審原則。
- 剪影片時試一次「名詞換動詞」：不要說「幫我做一支影片腳本」，改說「讓觀眾在 30 秒內決定訂閱」——觀察 Agent 提出的手法是否完全不同。
