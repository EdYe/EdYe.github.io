[核心摘要]

Claude Code 的威力不在於更強的提示詞，而在於分層搭建基礎設施。本片提出 11 個層級的完整藍圖：從資料夾結構、指令檔、工作階段管理、記憶層，進階到技能、子代理、外部工具整合、鉤子自動化，最終組合成端對端工作流程與能自我維護的元系統。全程無需寫程式，即可將事業營運（行銷、銷售、內容、客服）交由 Claude Code 系統化運轉，解決「只用皮毛、成果無法累積」的痛點。

[詳細重點整理]

## 1. 資料夾結構決定一切 [00:00:45]

啟動 Claude Code 的所在資料夾，決定了它的行為、可見範圍、權限與遵循的規則。就像公司裡人資、業務、財務各有辦公室，不同事業職能應各自建立專屬資料夾，否則檔案散亂、無法按任務類型控制行為。講者的 AI 總部內含「進行中專案」（各 AI 團隊的子資料夾）、資料層（專案記憶）與公司大腦「AI 成長引擎」。在銷售資料夾啟動工作階段，Claude Code 自動繼承銷售團隊的流程、行為與工具。

**關鍵概念：目錄即行為邊界（Directory as Behavior Boundary）**——資料夾不只是檔案收納，而是 Claude Code 的角色與權限容器。

## 2. 指令檔三件套 [00:03:26]

三種主要指令檔會在每次工作階段載入上下文視窗（session 記憶）：

- [**CLAUDE.md**](http://CLAUDE.md)：等同系統提示詞，定義 Claude Code 該做什麼
- [**rules.md**](http://rules.md)：特定任務類型或情境下要遵循的規則
- **settings.json**：JSON 設定檔，包含權限拒絕、鉤子（hook）等進階組態

由於指令會消耗 token 並佔據上下文空間，必須精簡。講者將 [CLAUDE.md](http://CLAUDE.md) 當作**路由器（Router）**——只做索引，指向正確的流程檔、文件與腳本，兼顧精簡與精確。

**關鍵概念：指令即路由器（Prompt as Router）**。

## 3. 工作階段管理 [00:06:36]

多數人開工作階段做事就關掉，導致成果流失、待辦事項無人追蹤。正確做法：

- 開始時給工作階段一個明確目標
- 結束時執行固定的**收尾流程（closing routine）**，確保脈絡傳遞、無遺漏待辦
- 骨幹是**工作階段帳本（session ledger）**——一個儲存所有進行中工作階段的資料庫，並透過指令檔讓 Claude Code 知道帳本的存在與用法
- 新功能 SendMessage 允許平行工作階段互傳訊息，建立資料交換層

**關鍵概念：工作階段帳本（Session Ledger）**——沒有它，關掉視窗的那一刻你就失去了掌控。

## 4. 三層記憶架構 [00:08:07]


| 層級  | 內容                                                             | 掌控權            |
| --- | -------------------------------------------------------------- | -------------- |
| 第一層 | [CLAUDE.md](http://CLAUDE.md)、[rules.md](http://rules.md) 指令記憶 | 完全掌控，但受上下文飽和影響 |
| 第二層 | 硬碟上結構化的記憶檔（專案記憶、詮釋資料），由指令檔主動指向                                 | 完全掌控           |
| 第三層 | Claude Code 自動管理的 [memory.md](http://memory.md)                | 掌控權低，易膨脹雜亂     |


第三層是最大盲區：Claude Code 從互動回饋中推斷記憶條目，很快擁擠不堪。解法是定期請它修剪、壓縮、移除重疊與過時內容——講者用 Windows Task Scheduler 排定自動化工作階段，專責清理記憶檔。

**關鍵概念：記憶蒸餾（Memory Distillation）**。

## 5. 把工作流程轉成技能（Skill）[00:11:11]

技能是一個資料夾加上作為路由器的 [SKILL.md](http://SKILL.md)，內含詮釋資料（YAML front matter）、描述與指向的指令檔、知識檔或腳本。其威力在於結合兩種特質：

- **腳本的確定性**：可重複、可預測、有紀律
- **LLM 的非確定性智慧**：能隨機應變處理預料之外的情境

運作機制是**漸進式揭露（Progressive Disclosure）**：工作階段開始時只載入所有技能的描述（輕量），有工作要做時才比對描述、探索 [SKILL.md](http://SKILL.md)、按需讀取其他資源。避免塞爆上下文視窗，模型更專注、表現更好。

要把流程變技能，只需在滿意的工作階段結束後要求 Claude Code 把成功流程打包。更進階的做法是使用**後設技能（Meta Skill）**——教 Claude Code 打造技能的技能，如 Anthropic 官方 GitHub 程式庫中的 skill creator（可直接請 Claude Code 自行安裝）。

**關鍵概念：確定性與智慧的混合體（Deterministic-Intelligent Hybrid）**。

## 6. 子代理（Subagent）團隊 [00:16:52]

子代理是擁有獨立上下文視窗的專家，存放在 .claude/agents 資料夾。檔案結構與技能相似：YAML 標頭定義名稱、描述、可用工具與模型，後接系統提示詞。核心優勢：

- **隔離的上下文視窗**：繁重工作不汙染主對話工作階段
- **新的眼光**：避免確認偏誤——讓模型在同一對話中評估自己的成果，多半帶有偏見
- 子代理之間現已可互相傳訊息，Claude Code 能產生並協調多個專家協作

**關鍵概念：上下文隔離（Context Isolation）**。

## 7. 外部工具整合 [00:19:10]

讓 Claude Code 對 CRM、電子郵件、ERP、任務管理系統做到三件事：拉取資料、推送資料、執行功能。整合路徑有四種：

- 本地腳本呼叫 API
- **MCP**：代理協定，讓 AI 代理發現並執行外部應用的工具
- CLI（命令列版本）——講者個人偏好
- 平台內建連接器（數量有限，僅適用特定工具）

實戰案例：客戶通話結束後，Claude Code 透過 Google Workspace CLI 得知會議，設定 cron 排程監看 Google Drive 上的錄影檔與逐字稿，偵測到後由子代理依講者框架分析、用技能產出報告與兩頁 PDF 工作計畫、撰寫並寄出郵件——全程無程式設計，只是整理得當的 Markdown 檔加一個排程任務。n8n、Zapier 等無程式碼工具的複製貼上時代就此結束。

**關鍵概念：端對端工作流程（End-to-End Workflow）**。

## 8. 鉤子（Hook）：重新引入確定性 [00:27:27]

技能與子代理由 LLM 依描述比對決定是否使用，不具確定性——上下文一滿，模型就會忘記。鉤子解決這個問題：**以程式化、確定性的方式偵測事件並觸發動作**。

事件類型包括：SessionStart（工作階段開始）、Stop（完成工作）、PreToolUse（使用工具前）、PostToolUse（使用工具後）、UserPromptSubmit（每次送出提示）、SubagentStart（子代理啟動）。還可依資料夾、檔案類型等參數精細調整觸發條件。觸發的動作可以是注入上下文、執行腳本，或串接整條子代理＋技能＋外部工具的完整工作流程。

鉤子也是實作**迴圈（Loop）**的關鍵：例如 Claude 用 Write 工具寫完文案 MD 檔時，PostToolUse 鉤子自動產生一個子代理用另一套框架檢查文案品質，回報主工作階段修正——讓輸出的出現自動觸發驗證，資訊回饋到流程起點。

**關鍵概念：確定性注入（Determinism Injection）**——懂了這一點就勝過 99.99% 談 AI 的人。

## 9. 手機存取 [00:33:13]

- **遠端控制**：輸入 /remote-control，同一工作階段即可在 [claude.ai](http://claude.ai) 與手機 App 上使用
- **頻道功能**：透過 Telegram 存取對話工作階段，打造「AI 執行助理」
- 限制：電腦必須開機。最便宜的解法是約 100 美元的迷你電腦 24 小時運轉，透過 GitHub 同步 AI 工作區，筆電關機也能遠端工作

**關鍵概念：隨身 AI 工作區（Pocket AI Workspace）**。

## 10. 組合成工作流程 [00:36:45]

前九級是基礎架構（資料夾、指令、工作階段）與原料（技能、代理、外部工具、鉤子），第十級將它們組合成「食譜」。實例是講者的短影音剪輯機器：腦力傾倒技能接收語音想法（不用提示詞——好的系統不需要提示詞）→ 團隊寫腳本 → 分身虛擬人像錄製 → 本地工具分析影片影格 → 文案專家與外部觀眾子代理多輪批評調整 → 代理團隊用 Kling AI、Remotion、Pexels 等外部工具製作 B-roll 與動態圖像 → 每張圖片自動用 Claude 視覺做品質檢查、有瑕疵就重新生成 → 產出可直接發布的短影音。這條流水線實際上是講者最主要的獲客工具。

**關鍵概念：管線化營運（Pipeline Operations）**。

## 11. 自我維護的元系統 [00:41:29]

系統會隨使用不斷膨脹而趨於混亂（**熵，熱力學第二定律**），效能逐漸下降。第十一級是建立一個「不靠你」就能維護並改進系統的系統：

- 工作層面：每個工作階段結束時，用鉤子觸發審查迴圈，以標準驗證產出品質
- 系統層面：排程自動化每週審查 [memory.md](http://memory.md) 與技能，評估哪些最新、重複、過時並清理，再透過「決策套件」技能產出十分鐘可審閱的精簡報告，供你決定處理或捨棄
- 根據實際使用觀察改進，而非理論

## 12. 定位自己：你在第幾級 [00:46:36]

- 第 1–5 級（資料夾、指令、工作階段、記憶、技能）：建立 AI 工作空間，多數人只做到指令＋一點記憶和技能，忽略資料夾與工作階段管理
- 第 6–9 級（子代理、外部工具、鉤子、手機存取）：擴展能力邊界
- 第 10 級：組合成精密工作流程，擁有一套 AI 系統
- 第 11 級：99.99999% 的人缺少的自我維護元系統

[結論與行動建議]

**啟發金句**：LLM 沒有紀律，程式才有紀律——真正強大的系統，是把兩者結合，讓彼此彌補弱點。

**具體行動建議**：採用 **F-S-S-H-M 法則**——**F**older（先把資料夾結構規劃成職能辦公室）→ **S**ession（建立工作階段帳本與收尾流程）→ **S**kill（把滿意的流程打包成技能，用 skill creator 後設技能加速）→ **H**ook（對「每次都必須發生」的事用鉤子注入確定性）→ **M**aintenance（最後建立自我維護的元系統，對抗熵）。順序不可顛倒：每一層都建立在前一層之上。

**生活實踐建議**：

- 從你的工作挑一個每週重複做的流程（如會議記錄、影片剪輯、客戶回報），在工作階段結束後請 Claude Code 打包成技能，下週驗證重製品質
- 給每個事業職能（內容、銷售、客服）各建一個資料夾，各自放專屬的 [CLAUDE.md](http://CLAUDE.md)，實測「在哪裡啟動、就繼承什麼行為」
- 對你最在意的產出（文案、影片、報告）加一個 PostToolUse 鉤子，自動派子代理扮演「毫無背景的外部觀眾」批評驗證，消除確認偏誤
- 用 Windows Task Scheduler 或 cron 排一週一次的記憶與技能清理，確保系統不隨時間膨脹失序
