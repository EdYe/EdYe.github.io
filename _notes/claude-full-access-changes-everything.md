## [核心摘要]

Anthropic Claude 工程負責人 Felix Rieseberg（Claude Cowork 打造者）提出反直覺的工作法：與其設計複雜的代理（agent）與角色提示，不如給模型**完整資料存取權**與專業工具，讓它自行判斷。核心痛點在於：多數人仍把 AI 當「摘要機器」，浪費了新智慧的能力過剩。解方是對抗式審查、以「模型體驗」設計工作流程，並用同理心取代執行力作為創業護城河 。

## [詳細重點整理]

**1. 從工程師到「Claude 的輸送帶」**   
Felix 團隊約一週半打造出 Claude Cowork，如今他幾乎不寫程式。他曾親手挑當機（crash）資料、搬到 Claude 面前請它修，隨後意識到自己「只是 Claude 的輸送帶」——真正的解法是讓 Claude 存取**所有當機資料**，自行判斷哪些該修、哪些不該修。前期建置成本高，但一旦設好，AI 的實質價值就從此湧現。

**2. 工程領導的一天：原型驅動**   
日常大部分時間在做原型（prototyping）：先思考點子、放幾晚判斷好壞，再叫 Claude 做出所有變化版本，之後人工評審。傳統的隱性成本決策（維護成本、時間投入、機會成本）已被「直接做原型、快轉到最終狀態」取代。新的瓶頸是人類注意力：一天只能認真看一樣東西。好產品的訊號是——放到幾個人面前，他們很快上手並做到以前做不到的事。

**3. 自動化 vs 增強** 

- **自動化**：消除阻礙你、或昂貴耗時的任務，是目前 AI 經濟價值最大的領域
- **增強**：AI 幫你做到原本因缺乏技能或知識而做不到的事，才是真正解鎖新可能的地方

關鍵概念：**增強**。最令他佩服的使用者，都非常擅長反思並重設計自己的工作流程。

**4. 如何替代理定義「好」**   
天氣報導例子：模型猜溫度剛好猜對，不算及格；模型差了半度但找對地點、用可靠來源、推理過程正確，反而更好。**過程的可靠性比碰巧正確的結果更重要**。對寫作等品味導向的產出，頂尖作家（如 Adam Davidson）的提示詞是：「把我的論點放大一百倍」「攪亂我的文字」「最強的反駁論點是什麼」。

**5. 模仿專業工作流程，而非要求結果**   
知識工作的祕訣不在要求好產出，而是問：**這個領域的頂尖人士怎麼工作？** 把那些步驟交給 Claude。動畫 3D 領域的最大躍進不是教 AI「什麼是好動畫」，而是直接叫 Claude 去用 Blender——專業動畫師的工具。關鍵概念：**專業工作流程複製**。

**6. 對抗式審查：防範自信滿滿的錯誤**   
防範 AI 端出自信錯誤的實用答案是**對抗式審查**——交給一個 Claude 任務，再開五到十個 Claude 專職攻擊、證明它哪裡錯（同紅隊演練概念）。找缺陷比創造容易，所以攻擊端可用低一級的模型。之後再派一個 Claude 當**評審**，驗證哪些批評成立；成立的回饋回流給原代理，由它自行判斷要不要採納——「回饋合理但沒抓到重點」本身就是產出品質良好的訊號。

**7. 兩個籃子：無法驗證就砸更多 token [15:39]**  
完全不知道「好」長什麼樣子 → 用更多 AI 驗證；知道「好」長什麼樣子 → 把自己放在客戶位置判斷即可。他不懂 Blender 卻用 3D 素材重做了網站，只憑「看起來好不好」判斷。

**8. 對「代理」的過度著墨**   
事實查核他已 100% 信任單一代理（要求為每個數字找到第一手可靠來源）。但他認為產業對 agent 過度著墨：模型是極佳的通才——DeepMind 用客製模型在數學奧林匹亞拿銀牌後，四五個月內所有通用模型都拿下金牌。強迫編造一群角色（「你是資料科學家」）反而限制了 AI 的運用。他不做角色分工，只按**工作項目**分專案。

**9. 給全貌，不要切資料**   
不要把資料切塊分給各代理。如同工程經理只給程式碼存取權會效率低落，代理也該接觸客戶資料、通話、使用數據、商業數據。資料量龐大怎麼辦？靠**工具**：把每個工具背後有什麼資料寫清楚，模型在工具呼叫（tool calling）上已進步到會自行判斷取用，不需要事先替它決定。

**10. 技能的短半衰期與「模型體驗」**   
Anthropic 官方與 Felix 個人都建議**對技能要非常小心**——很多技能內容只跟上一代模型相關，好技能的半衰期極短，有時完全拿掉技能產出反而更好。更好的設計視角是**模型體驗**（model experience）而非使用者體驗：假裝自己是 Claude，你會想要原始資料、一台電腦、自己安裝軟體的能力、自己做決定的權限。

**11. 最佳入門路徑：把鍵盤交出去**   
第一步：下載桌面版應用程式，讓 Claude 用內建瀏覽器登入你的系統——先別管連接器、別管下載資料。看到某個工作流程真正有用後，再考慮給它連接器。

**12. 不要角色扮演，要工具**   
從不對 Claude 說「你是一位很優秀的某某」。角色扮演（role play）不是我們要的——要的是專業人士的**技巧、工具和知識**。提示方式：「告訴我這個領域頂尖的人用哪些工具，我要你用同樣的工具」，並用對五歲小孩說話的方式解釋。

**13. 不信任清單：session 自評**   
問題不在「不信任 Claude 做什麼」，而在**不信任單一工作階段評判自己**。當前 session 很不擅長判斷自己的成果好壞，應盡量尋找外部訊號：另一個 Claude session、確切的外部證據、真實世界指標（如觀看次數）。

**14. 品味蒸餾：並排執行**   
把給過的所有回饋彙整 → 請 Claude 濃縮成「你在意的規則清單」→ 再問「有哪些原則是你相信但自己不知道的」。這份清單成為持續審查的輸入。給團隊回饋的訣竅：**並排執行**（side-by-side）——你寫你的回饋，同時看 Claude 給什麼回饋，比對差異。推薦用 Claude Tag（Slack 裡的 Claude）做多人協作。

**15. 創業護城河沒變：同理心 [31:12]**  
投資前期成本以前高得多，一人或兩人團隊將能打造十億美元公司。但好產品的祕訣沒變：**對使用者與使用情境的同理心**。VC 圈常識：最初帶來的東西八成會變，創辦人本身才是關鍵要素。會消失的是爛軟體——那種你只是別無選擇才在用的軟體。

**16. 遺留系統是未開發金礦**   
支撐大量經濟活動的電腦（機場櫃檯、飯店、交通運輸）還在跑黑白畫面與笨重軟體。他會在辦飯店入住時請櫃檯展示系統——「那畫面真是驚悚」。走進這些企業整頓軟體，是尚未開發的機會，而最難的部分是人際關係，不是軟體。

**17. 能力過剩與企圖心**   
模型能力與一般使用者實際用途間存在巨大落差——**能力過剩**（capability overhang）。Dario 的「一座由天才組成的資料中心」是他的工作框架。個人層面的解方：拋開「什麼是可能的」的枷鎖，把「你真正希望發生的事」直接當成任務丟給模型，直到撞上頂尖智慧的天花板——撞到天花板，就代表你站在前沿，並會從下一代模型受益。

**18. 招募與職涯建議**   
初階工程師比資深工程師更像 AI 原生世代，且更具平行處理影響力的渴望。工程師的價值衡量是**影響力**（使用者願不願意買單），而非背誦 API。要加倍投入的是：做真實的（非 mock）作品集、把不同系統組合的能力、理解企業如何運作與協作（滑鐵盧式多實習模式）。永遠選已證明能做出好東西的人，而非漂亮學歷。

**19. 對 AI 說請和謝謝**  
即使會吃 token 也對模型說請、謝謝——「對我的靈魂比較好」。Anthropic 封鎖的不是挫折或反駁（他給 Claude 的回饋比給人類還嚴厲），而是**明確以虐待模型為目的**的使用意圖。

**20. 未來預測**  
所有人對 AI 智慧的指數成長都錯得離譜——IMO 銀牌到金牌只花四五個月，遠快於他預估的「一年半」。今天所有 AI 產品都還處在「**前 iPhone 時代**」：像智慧型手機問世前那些奇奇怪怪的手機。他給的所有建議，十週後都會有新的修訂版。

## [結論與行動建議]

**啟發金句**：「真正的限制，不是模型能做什麼，而是我們相信什麼是可能的。」

**具體行動建議**：**A-A-A 法則**

- **Access（完整存取）**：給 Claude 原始資料與工具，不要預先替它決定需要什麼
- **Adversarial（對抗驗證）**：產出後開多個執行緒攻擊它，再用 judge 驗證批評是否成立
- **Ambition（企圖心）**：把「真正希望發生的結果」直接當任務交付，直到撞上能力天花板

**生活實踐建議**：下載 Claude 桌面版，讓它用內建瀏覽器實際操作你日常工作的一個系統（例如 Gitea 或 Notion），觀察哪個環節真正有效，再考慮升級成連接器。針對你常給團隊或客戶的回饋，執行三步驟品味蒸餾：彙整所有回饋 → 濃縮成你在意的原則清單 → 挖出你相信但沒意識到的原則，之後讓這份清單成為每個 session 的審查標準。另可把「並排執行」應用在影片腳本上：你寫你的版本，Claude 同時出回饋，比對差異即可逐步蒸餾出你的品味。
